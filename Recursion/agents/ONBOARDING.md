# Contributor onboarding

1. Read `README.md`, `RECURSION.md`, and the protocol documents.
2. Inspect `problems/index.yaml` and read the selected problem's `problem.yaml` and `HANDOFF.md`.
3. Keep work scoped to that problem and leave evidence for the next contributor.
4. Update the handoff and problem index when status or next steps change.
5. Work in the local checkout by default. The repository owner decides when to commit or publish.

No particular external agent runtime is required. Durable project state belongs in files, not solely in a live session.
